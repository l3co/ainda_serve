# Roadmap Conventions

These conventions govern the structure, naming, linking, and lifecycle of planning documents generated by the incremental-planning skill.

---

## Directory Structure

All planning documents live under `planning/` at the project root.

```
planning/
├── roadmap.md              ← always present; primary document and index
├── discovery.md            ← when context is insufficient at start
├── architecture.md         ← when significant design decisions are required
├── risks.md                ← when the initiative has many independent risks
├── rollout.md              ← when production rollout needs its own strategy
├── decisions/
│   ├── decision-001-short-description.md
│   └── decision-002-short-description.md
└── phases/
    ├── phase-01-foundation.md
    ├── phase-02-core-implementation.md
    └── phase-03-validation.md
```

Do not create this entire structure for every plan. Use only the documents the complexity requires.

---

## File Naming Conventions

All file names must:

- Be written in English
- Use lowercase letters only
- Use kebab-case (`word-word-word`)
- Use numeric prefixes when order is meaningful
- Communicate intent clearly

| Type | Pattern | Example |
|---|---|---|
| Phase | `phase-NN-intent.md` | `phase-01-domain-model.md` |
| Decision | `decision-NNN-topic.md` | `decision-001-storage-strategy.md` |
| Roadmap | `roadmap.md` | fixed name |
| Discovery | `discovery.md` | fixed name |

**Prefer names that reveal intent:**

Good: `phase-02-payment-integration.md`
Good: `decision-001-event-processing-approach.md`

Avoid:
- `section1.md`, `section2.md`
- `things.md`, `misc.md`, `others.md`
- `implementation.md` (too generic)
- `phase-02.md` (no intent)

## Phase Numbering

Number phases starting from `01` with two digits: `phase-01`, `phase-02`, `phase-10`.

When adding phases to an existing plan, continue the existing numbering sequence. Do not renumber existing phases unless there is a structural reorganization — and document why.

When a phase is deferred or cancelled, keep its file but update its status. Do not delete the file.

---

## Allowed Statuses

Use exactly these values for phase and task statuses:

| Status | When to use |
|---|---|
| `Proposed` | Suggested but not yet confirmed |
| `Planned` | Confirmed and ready to be scheduled |
| `Ready` | Prerequisites complete; work can begin |
| `In Progress` | Work has started |
| `Blocked` | Cannot proceed; reason documented |
| `Completed` | All acceptance criteria met and verified |
| `Deferred` | Postponed; reason documented |
| `Cancelled` | Will not be done; reason documented |

**Initial creation:** use `Planned` or `Proposed` depending on how confirmed the plan is.

**Never use `Completed` during the planning activity.** A phase is Completed only after the user confirms it.

---

## Decision Statuses

| Status | When to use |
|---|---|
| `Proposed` | Decision suggested but not yet taken |
| `Accepted` | Decision confirmed by the user or clearly established in the project |
| `Rejected` | Decision considered and not taken; rationale documented |
| `Superseded` | Replaced by a newer decision; link to the replacement |
| `Deprecated` | No longer applicable |

## Relative Links

All links between documents must be relative. Never use absolute file system paths.

**From `planning/roadmap.md`:**
```markdown
- [Discovery](./discovery.md)
- [Phase 01 — Foundation](./phases/phase-01-foundation.md)
- [Decision 001 — Persistence Strategy](./decisions/decision-001-persistence-strategy.md)
```

**From `planning/phases/phase-02-implementation.md`:**
```markdown
- [Roadmap](../roadmap.md)
- [Previous phase](./phase-01-foundation.md)
- [Next phase](./phase-03-validation.md)
- [Decision 001](../decisions/decision-001-persistence-strategy.md)
```

**From `planning/decisions/decision-001-name.md`:**
```markdown
- [Roadmap](../roadmap.md)
- [Phase 02](../phases/phase-02-implementation.md)
```

Do not include links to documents that do not yet exist. Add links when the document is created.

## Roadmap Structure

`planning/roadmap.md` must contain these sections in this order:

```markdown
# Implementation Roadmap: {{PROJECT_OR_FEATURE_NAME}}

## Overview
## Goal
## Current state
## Target state
## Success criteria
## Scope
### In scope
### Out of scope
## Assumptions
## Constraints
## Architecture summary
## Delivery strategy
## Phase overview

| Phase | Objective | Depends on | Deliverable | Status |
|---|---|---|---|---|

## Critical path
## Parallel work
## Dependency map
## Risk summary
## Validation strategy
## Rollout strategy
## Open questions
## Planning documents
```

All sections must be present. Sections that do not apply should say "None identified at this time."

## Phase Structure

Every phase document must contain these sections:

```markdown
# Phase NN — Phase Name

## Objective
## Value delivered
## Scope
### Included
### Excluded
## Prerequisites
## Dependencies
## Files involved
## Technical approach
## Tasks
## Testing
## Validation
## Acceptance criteria
## Risks
## Rollback or recovery
## Completion checklist
## Navigation
```

---

## Task Structure Within a Phase

```markdown
### Task N.N — Task name

**Objective**
What specific result this task delivers.

**Why**
Why this task is necessary at this point in the plan.

**Files**
- `path/to/file`: Existing file — what changes.
- `path/to/new-file`: New file — what it will contain.
- `path/to/uncertain`: Proposed path — needs confirmation.

**Implementation**
1. First step.
2. Second step.
3. Third step.

**Tests**
- Expected test case.
- Success scenario.
- Error scenario.
- Relevant edge case.

**Validation**
- What to run or check.
- Observable outcome.
- Evidence of completion.

**Acceptance criteria**
- [ ] Objective criterion 1.
- [ ] Objective criterion 2.

**Risks**
- Risk — mitigation.

**Dependencies**
- Task, phase, or decision required before this one.
```

## Navigation Section

Every phase document must end with a Navigation section:

```markdown
## Navigation
- [Roadmap](../roadmap.md)
- [Previous phase](./phase-NN-name.md)   ← omit if Phase 01
- [Next phase](./phase-NN-name.md)        ← omit if last phase
```

---

## Updating Existing Plans

When `planning/roadmap.md` already exists:

1. Read the existing document before making any changes
2. Preserve existing phases, their numbering, and their history
3. Add new phases by continuing the existing sequence
4. Update the phase overview table
5. Update dependency maps and navigation links
6. Register superseded decisions with a `Superseded by` reference
7. Do not delete existing content

When a decision is superseded:

```markdown
## Status
Superseded by [Decision 004](./decision-004-new-strategy.md)
```

When a phase is deferred:

```markdown
## Status
Deferred — pending resolution of [open question on storage strategy](../roadmap.md#open-questions).
```

## Proportionality Rule

| Scope | Minimum documents | Maximum reasonable |
|---|---|---|
| Trivial change (1–2 tasks) | `roadmap.md` + 1 phase | Same |
| Small feature (3–6 tasks) | `roadmap.md` + 2–3 phases | + `discovery.md` |
| Medium feature (6–15 tasks) | `roadmap.md` + 3–4 phases + `discovery.md` | + 1–2 decisions |
| Large initiative | `roadmap.md` + `discovery.md` + phases + decisions | + `architecture.md`, `risks.md`, `rollout.md` |

Do not create documents to fill a template. Create documents to communicate information.
